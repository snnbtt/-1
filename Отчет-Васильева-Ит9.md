# 1. Цель работы
Цель лабораторной работы — изучить основы объектно-ориентированного программирования на языке Java: создание классов, проектирование конструкторов с перегрузкой и делегированием, организация взаимодействия между объектами, переопределение метода toString(), перегрузка методов, работа со ссылками и графами объектов.

# 2. Постановка задачи
В соответствии с вариантом 3 необходимо реализовать следующие задания:

- Задание 1.3 — Имена. Создать класс Name для хранения ФИО. Имя приводится к строке в формате «Фамилия Имя Отчество», незаполненные поля (null) не выводятся.
- Задание 2.2 — Человек с именем. Создать класс Person, использующий объект Name для хранения имени, и поле роста. Вывод в формате «Имя, рост».

- Задание 5.2 — Кот мяукает. Создать класс Cat с методом meow() и перегруженным meow(int n).


# 5. Описание работы программы и алгоритмы решения

## Задание 1.3 — Имена

Алгоритм решения:
1. Создать класс Name с тремя приватными полями: surname, name, patronymic.
2. Написать три конструктора: только имя; фамилия + имя; фамилия + имя + отчество. Все они вызывают главный конструктор через this(...).
3. Переопределить toString(): с помощью StringBuilder собрать строку, добавляя только те поля, которые не равны null.
4. Создать три объекта: new Name("Клеопатра"), new Name("Пушкин", "Александр", "Сергеевич"), new Name("Маяковский", "Владимир").
5. Вывести через System.out.println().

Пояснение:
Три конструктора реализуют перегрузку. Все они делегируют к главному конструктору с тремя параметрами через this(...). Вызов this(...) должен быть первой инструкцией в конструкторе. Метод toString() собирает строку через StringBuilder, пропуская null-поля, и возвращает результат через trim() для удаления лишних пробелов.

## Задание 2.2 — Человек с именем

Алгоритм решения:
1. Создать класс Person с полями Name name и int height.
2. Написать конструктор Person(Name name, int height).
3. Переопределить toString(): вернуть name + ", " + height — автоматически вызывается toString() у объекта Name.
4. Создать три объекта Person, передавая готовые объекты Name и рост.
5. Вывести через System.out.println().

Пояснение:
Поле name имеет тип Name (объект), а не String. При выводе через name + ", " + height автоматически вызывается toString() у объекта Name, поэтому выводится полное ФИО, а не хэш объекта. Это работает потому, что мы переопределили toString() в классе Name.

## Задание 2.3 — Человек с родителем

Алгоритм решения:
1. Добавить в класс Person поле Person parent.
2. Написать конструктор Person(Person parent, String name, int height) — принимает отца, строку-имя и рост.
3. Внутри конструктора создать объект Name из строки через new Name(name).
4. Проверить: если фамилия не задана (null) и у отца есть фамилия — присвоить фамилию отца через name.setSurname(parent.name.getSurname()).
5. Проверить: если отчество не задано (null) и у отца есть имя — образовать отчество через метод formPatronymic(parent.name.getName()).
6. Метод formPatronymic(): если имя оканчивается на «й» — заменить «й» на «евич» (Сергей → Сергеевич), иначе добавить «ович» (Иван → Иванович).
7. Создать Ивана: new Person(new Name("Чудов", "Иван"), 180).
8. Создать Петра: new Person(ivan, "Пётр", 175) — от Ивана наследуется фамилия «Чудов» и образуется отчество «Иванович».
9. Создать Бориса: new Person(pyotr, "Борис", 170) — от Петра наследуется «Чудов» и образуется «Петрович».
10. Вывести всех троих.

Пояснение:
Конструктор с отцом вызывает главный конструктор через this(new Name(name), height, parent). В главном конструкторе проверяется parent != null, и если да — фамилия наследуется от отца, а отчество образуется от имени отца. Метод formPatronymic() — статический, обрабатывает окончание «й» (заменяется на «евич») и все остальные случаи (добавляется «ович»).

## Задание 3.3 — Города

Алгоритм решения:
1. Создать класс City с полями String name и Map<City, Integer> paths.
2. Использовать LinkedHashMap для сохранения порядка добавления путей.
3. Написать конструктор City(String name), инициализирующий пустую карту.
4. Написать метод addPath(City city, int cost) — добавляет запись в карту.
5. Переопределить toString(): вывести название города, затем в квадратных скобках список путей в формате «город:стоимость» через запятую.
6. Создать шесть городов: A, B, C, D, E, F.
7. Добавить связи: a→b(5), a→f(1), a→d(6), f→b(1), f→e(2), e→d(2), d→c(4), c→b(3).
8. Вывести все шесть городов.

Пояснение:
LinkedHashMap выбран вместо HashMap, потому что он сохраняет порядок добавления элементов. Это важно для корректного вывода путей в том порядке, в котором они были заданы. Каждый город хранит карту связанных городов и стоимостей. Метод toString() проходит по записям карты и формирует строку вида «A: [B:5, F:1, D:6]».

## Задание 4.5 — Создаём Имена

Алгоритм решения:
1. Класс Name уже имеет три перегруженных конструктора из задания 1.3: Name(String name), Name(String surname, String name), Name(String surname, String name, String patronymic).
2. Создать первое имя: new Name("Клеопатра") — только личное имя.
3. Создать второе имя: new Name(null, "Александр", "Сергеевич") — фамилия не задана, только имя и отчество.
4. Создать третье имя: new Name("Пушкин", "Владимир") — фамилия и имя, отчество не задано.
5. Создать четвёртое имя: new Name("Маяковский", "Христофор", "Бонифатьевич") — все три параметра.
6. Вывести все четыре. Метод toString() пропускает null-поля.

Пояснение:
При создании имени «Александр Сергеевич» фамилия не указана (null), поэтому в выводе она отсутствует — выводится «Александр Сергеевич». Для «Пушкин Владимир» не задано отчество — оно также пропускается, выводится «Пушкин Владимир». Это демонстрирует перегрузку конструкторов — три разных способа создать объект одного класса.

## Задание 4.6 — Создаём Человека

Алгоритм решения:
1. Написать главный конструктор Person(Name name, int height, Person parent) — единственное место, где выполняются присвоения полей.
2. Написать три дополнительных конструктора, каждый вызывает главный через this(...):
   - Person(String name, int height) → this(new Name(name), height, null)
   - Person(String name, int height, Person parent) → this(new Name(name), height, parent)
   - Person(Name name, int height) → this(name, height, null)
3. В главном конструкторе, если parent != null:
   - Если фамилия не задана и у отца есть фамилия — наследовать фамилию отца.
   - Если отчество не задано и у отца есть имя — образовать отчество через formPatronymic().
4. Создать Льва: new Person("Лев", 170) — только имя и рост.
5. Создать Сергея: new Person(new Name("Пушкин", "Сергей"), 168, lev) — фамилия задана, отчество образуется от «Лев» → «Львович».
6. Создать Александра: new Person("Александр", 167, sergey) — фамилия наследуется «Пушкин», отчество от «Сергей» → «Сергеевич».
7. Вывести всех троих.

Пояснение:
Все присвоения полей (this.name = ..., this.height = ..., this.parent = ...) выполняются только в главном конструкторе с тремя параметрами. Остальные конструкторы лишь преобразуют аргументы и делегируют к нему через this(...). Это avoids дублирование кода. При наличии отца фамилия наследуется, а отчество образуется: «Лев» не оканчивается на «й», поэтому добавляется «ович» → «Львович». «Сергей» оканчивается на «й», поэтому «й» заменяется на «евич» → «Сергеевич».

## Задание 5.2 — Кот мяукает

Алгоритм решения:
1. Создать класс Cat с приватным полем String name.
2. Написать конструктор Cat(String name).
3. Переопределить toString(): вернуть "кот: " + name.
4. Написать метод meow(): вывести name + ": мяу!".
5. Написать перегруженный метод meow(int n): с помощью StringBuilder собрать n «мяу», разделённых дефисом, добавить «!» в конце.
6. Создать кота: new Cat("Барсик").
7. Вывести кота через System.out.println(cat).
8. Вызвать cat.meow() и cat.meow(3).

Пояснение:
Метод meow() без параметров выводит одно «мяу!». Перегруженный meow(int n) собирает n «мяу» через StringBuilder, разделяя их дефисом: «мяу-мяу-мяу!». Это демонстрирует перегрузку методов — два метода с одинаковым именем, но разными параметрами. Компилятор выбирает нужный метод по типу и количеству аргументов.
